# 시험 전 10일 학습 계획 (하루 1시간)

시험 10일 전부터 **하루 1시간씩** 이 저장소만으로 준비하는 계획입니다. 1일차가 D-10, 10일차가 시험 전날(D-1)입니다.

> 예: 9월 26일에 시작하면 10월 5일이 10일차, 10월 6일이 시험일입니다.

## 계획을 세운 기준

- **여섯 세트를 전부 풀 수는 없습니다.** 102문항의 목표 시간만 더해도 660분이라 10시간을 넘습니다. 그래서 **기본 난이도(D·E·F)** 를 중심으로 약 40문항을 풀고, 심화(A·B·C)는 매일 `여유가 있으면` 항목으로만 둡니다.
- **순서는 도구 → 설치·구성 → 워크로드 → 네트워크 → 스토리지 → 트러블슈팅 → 실전 → 정리** 입니다. 트러블슈팅(30%)은 앞에서 배운 구성 요소가 망가진 상황을 다루므로 뒤에 두고, 이틀을 씁니다.
- **하루 1시간은 모두 같은 틀로 씁니다.** 읽기 15분, 문제 풀이 25~35분, 풀이 대조와 기록 10~15분입니다.
- **문제는 `question.md` 만 보고 손으로 풉니다.** 다 푼 뒤에 `solution.md` 를 열고, 한글 해석으로 영문을 제대로 읽었는지부터 확인합니다.

## 시작 전에 확인할 것

- **연습 클러스터가 있어야 합니다.** kubeadm 업그레이드, 노드 NotReady, 정적 파드 장애 문제는 VM 두 대 이상으로 만든 kubeadm 클러스터에서만 제대로 재현됩니다. kind·minikube로는 리소스를 만드는 문제만 풀 수 있습니다.
- **killer.sh 시뮬레이터**: CKA를 등록하면 시뮬레이터 세션 2회가 함께 제공됩니다(세션마다 36시간 이용). 이 계획의 하루 1시간에는 넣지 않았지만, 시간이 나는 주말이나 9일차 전후에 한 번 써 보면 실전 난이도를 가늠할 수 있습니다.

## 매일 끝낼 때 기록할 것

1. 푼 문제의 `question.md` → `## My attempt` 에 입력한 명령 (틀린 것도 그대로)
2. 회차 `README.md` 의 `실제` 시간과 `결과` 칸
3. 틀린 문제는 `solution.md` 의 `## 오답 원인 / 배운 점`
4. 같은 주제를 두 번 틀리면 저장소 루트 [README.md](../README.md) 의 **반복 오답 목록**에 추가 — 10일차에 이 표를 다시 봅니다.
